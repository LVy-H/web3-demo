# Frontend Conventions & Standards

Technical standards for the Anonymous Web3 Voting System frontend. Every PR touching frontend code must follow these rules.

---

## Tech Stack (locked versions)

| Library | Version | Role |
|---------|---------|------|
| React | 19.x | UI framework (new JSX transform, `useTransition`) |
| TypeScript | ~5.9 | Strict mode, `erasableSyntaxOnly` |
| Vite | 8.x-beta | Bundler (Rolldown-based) |
| Tailwind CSS | 4.x | Utility-first styling (`@theme` directive, no config JS) |

## TypeScript Rules

**Strict mode is mandatory.** These flags are set in `tsconfig.app.json`:

```json
{
  "strict": true,
  "noUnusedLocals": true,
  "noUnusedParameters": true,
  "noFallthroughCasesInSwitch": true,
  "erasableSyntaxOnly": true
}
```

### Do's
- Use explicit types for function parameters and return values in hooks
- Use `as const` for constant arrays and objects
- Import types with `import type { ... }` (required by `verbatimModuleSyntax`)
- Type contract addresses as `` `0x${string}` ``

### Don'ts
- No `any` in new code. Use `unknown` and narrow with type guards.
- No `@ts-ignore` or `@ts-expect-error` without a comment explaining why
- No type assertions (`as`) unless the cast is provably safe (e.g., ABI-derived types)

## File Organization

```
src/
├── main.tsx              # Entry point (providers only, no logic)
├── App.tsx               # Router + wallet connection shell
├── config.ts             # wagmi config + exported contract addresses
├── env.d.ts              # Global type declarations (window.ethereum)
├── index.css             # Tailwind import + @theme tokens
├── pages/                # Route-level components (one per route)
│   ├── Home.tsx
│   └── Poll.tsx
├── hooks/                # Custom React hooks (one file per domain)
│   ├── useRegistry.ts
│   └── usePoll.ts
└── abi/                  # Contract ABI JSONs (auto-generated, don't hand-edit)
    ├── IZkPoll.json
    ├── PollRegistry.json
    └── ZkAnonVoting.json
```

### Naming Conventions

| What | Convention | Example |
|------|-----------|---------|
| Page components | PascalCase, default export | `export default function Home()` |
| Hook files | camelCase with `use` prefix | `useRegistry.ts` |
| Hook functions | camelCase with `use` prefix | `useAllPolls()`, `usePollState()` |
| Interfaces/types | PascalCase | `PollInfo`, `PollState` |
| Constants | UPPER_SNAKE_CASE | `REGISTRY_ADDRESS` |
| Event handlers | `handle` + action | `handleCreatePoll`, `handleVote` |
| State setters | `set` + noun | `setTitle`, `setOptions` |
| Boolean state | `is` / `has` prefix | `isOwner`, `hasVoted` |
| ABI files | PascalCase matching contract name | `ZkAnonVoting.json` |

### File Rules
- One page component per file, one route per page
- One hook file per domain (registry, poll, etc.), multiple exported hooks per file
- No barrel files (`index.ts` re-exports) -- import directly from the source file
- ABI files are auto-generated by `npm run copy-abis` in the contracts package. Never hand-edit them.

## Tailwind CSS v4 Standards

### Theme Tokens

Define all custom design tokens in `index.css` using the `@theme` directive (Tailwind v4 syntax -- no `tailwind.config.js`):

```css
@import "tailwindcss";

@theme {
  /* Brand colors -- override or extend these for the project */
  --color-brand-primary: oklch(0.25 0.02 260);   /* slate-900 equivalent */
  --color-brand-accent: oklch(0.55 0.22 260);     /* blue-600 equivalent */

  /* Semantic colors */
  --color-success: oklch(0.60 0.15 160);           /* emerald-600 */
  --color-warning: oklch(0.65 0.15 80);            /* amber-600 */
  --color-danger: oklch(0.55 0.20 15);             /* rose-600 */
}
```

## wagmi / viem Patterns

### Contract Read (polling)

Use `useReadContract` with `refetchInterval` for live data:

```typescript
const { data, error, isPending } = useReadContract({
  address: pollAddress,
  abi: IZkPollABI.abi,
  functionName: 'getState',
  query: { refetchInterval: 2000 },
})
```

**Polling intervals:**
| Data type | Interval | Rationale |
|-----------|----------|-----------|
| Poll state | 2000ms | State changes are admin-triggered, need fast response |
| Options list | 5000ms | Rarely changes after creation |
| Vote results | 3000ms | Updates with each vote, balance freshness vs. RPC load |
| Poll list (registry) | 5000ms | New polls are infrequent |

### Contract Write

Always pair `useWriteContract` with `useWaitForTransactionReceipt`:

```typescript
const { data: hash, mutateAsync, isPending, error } = useWriteContract()
const { isLoading: isConfirming, isSuccess } = useWaitForTransactionReceipt({ hash })
```

**Button state pattern:**
```tsx
<button disabled={isPending || isConfirming}>
  {isPending ? 'Confirm in wallet...' : isConfirming ? 'Processing...' : 'Submit'}
</button>
```

### Error Handling

Always cast errors to `BaseError` for the `shortMessage` property:

```typescript
import type { BaseError } from 'wagmi'

// In catch block or error display:
const message = (error as BaseError)?.shortMessage ?? error?.message ?? 'Unknown error'
```

Map known revert strings to user-friendly messages (see UX Principles Rule 5).

### ABI Contract Config Pattern

Define reusable contract configs in hooks, not in page components:

```typescript
// hooks/usePoll.ts
import IZkPollABI from '../abi/IZkPoll.json'

export function usePollState(pollAddress: `0x${string}`) {
  return useReadContract({
    address: pollAddress,
    abi: IZkPollABI.abi,
    functionName: 'getState',
    query: { refetchInterval: 2000 },
  })
}
```

Pages consume hooks, never import ABIs directly:

```typescript
// pages/Poll.tsx
import { usePollState, usePollOptions } from '../hooks/usePoll'
```

**Exception:** Module-specific write operations (e.g., `castVote` on ZkAnonVoting) may import the module's ABI directly in the page, since these writes are not part of the shared `IZkPoll` interface.

### encodeFunctionData for Initialization

When creating polls through the registry, encode the module's `initialize()` call:

```typescript
import { encodeFunctionData } from 'viem'
import ZkAnonVotingABI from '../abi/ZkAnonVoting.json'

const initData = encodeFunctionData({
  abi: ZkAnonVotingABI.abi,
  functionName: 'initialize',
  args: [SEMAPHORE_ADDRESS, ownerAddress, options],
})
```

## React Patterns

### State Management

- **No global state library** (Redux, Zustand). wagmi + react-query handle all contract state.
- **Component-local state** for forms (`useState`)
- **localStorage** for persistent user data (Semaphore identity, vote receipts)
- **URL params** for navigation state (`useParams` for poll address)

### localStorage Keys

Use consistent, poll-scoped keys:

| Key Pattern | Value | Purpose |
|-------------|-------|---------|
| `semaphore-identity-${pollAddress}` | Token string | Persisted ZK identity |
| `voted-${pollAddress}` | Nullifier string | Proof that user voted |

### Hook Composition

Hooks should be thin wrappers around wagmi hooks. No business logic in hooks -- that belongs in event handlers in page components.

```typescript
// Good: thin hook
export function usePollState(addr: `0x${string}`) {
  return useReadContract({ address: addr, abi, functionName: 'getState', query: { refetchInterval: 2000 } })
}

// Bad: business logic in hook
export function useVotingFlow(addr: `0x${string}`) {
  const state = usePollState(addr)
  const [identity, setIdentity] = useState(null)  // Don't manage form state in hooks
  // ...complex flow logic
}
```

### Component Structure

Pages follow this structure:

```tsx
export default function PageName() {
  // 1. Router hooks (useParams, etc.)
  // 2. Wallet hooks (useAccount, etc.)
  // 3. Contract read hooks (usePollState, etc.)
  // 4. Contract write hooks (usePollWrite, etc.)
  // 5. Local state (useState)
  // 6. Derived values (const isOwner = ...)
  // 7. Effects (useEffect)
  // 8. Event handlers (async function handleX)
  // 9. Return JSX

  return (
    <div className="max-w-6xl mx-auto p-6">
      {/* Page content */}
    </div>
  )
}
```

### Loading & Error States

Every contract read must handle three states:

```tsx
const { data, error, isPending } = usePollState(address)

if (isPending) return <LoadingSkeleton />
if (error) return <ErrorMessage error={error} />
return <ActualContent data={data} />
```

For inline data (within a larger page), use conditional rendering:

```tsx
<span>{isPending ? '...' : data?.toString()}</span>
```

## Known Issues & Tech Debt

These are documented here so future work addresses them intentionally, not accidentally:

1. **App.css is legacy** -- contains unused Vite template styles. Safe to delete, just hasn't been prioritized.
2. **Module-level group state in Poll.tsx** -- `group` and `isGroupSynced` are declared outside the component. Works for single-poll views but would break if multiple polls rendered simultaneously. Acceptable for now.
3. **No form library** -- useState-based form management is fine for 2-3 fields. If forms grow (e.g., poll creation with advanced options), consider `react-hook-form`.
4. **Hardcoded refetch intervals** -- could be configurable via env vars or a constants file. Low priority.
5. **No toast/notification library** -- status messages use inline state. If we need persistent notifications (e.g., "vote confirmed!"), add `sonner` or `react-hot-toast`.

- [ ] No `any` types in new code
- [ ] All contract reads handle `isPending` and `error` states
- [ ] All contract writes show wallet/processing state on the button
- [ ] Error messages are human-readable (no raw revert strings)
- [ ] New hooks are in `hooks/`, not inline in page components
- [ ] Tailwind classes follow the documented color palette and spacing
- [ ] Works on 375px mobile width
